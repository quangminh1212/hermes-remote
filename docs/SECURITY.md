# Security

How Hermes Remote handles secrets, and where the API key lives.

## Where the API key lives

The API key is **never** stored in this repository. It exists in three places,
each for a specific reason:

### 1. The source of truth — the Hermes gateway on the PC

| | |
|---|---|
| **File** | `%LOCALAPPDATA%\hermes\.env` (Windows) |
| | `~/.local/share/hermes/.env` (Linux) |
| | `~/.config/hermes/.env` (alt Linux) |
| **Variable** | `API_SERVER_KEY` (64 hex characters) |
| **Consumed by** | the gateway listening on `API_SERVER_HOST:API_SERVER_PORT` (default `0.0.0.0:8642`) |

The key is generated by Hermes, not by this project. Override the search path
with `HERMES_ENV_FILE=<path>` if your `.env` lives elsewhere.

The pairing CLI reads this file to build the QR payload — it never writes to it
and never sends the key anywhere except the local pairing page.

### 2. The pairing payload — transient, on the PC

`/api/connect` and the QR code contain the key so the phone can pair without
typing it.

**This is why the pairing server binds to `127.0.0.1` only.** The key is in the
QR image, so anything that can reach `/api/connect` can pair with the gateway.
The server is deliberately not reachable from the LAN; the phone reaches the
*gateway* over the tunnel, not this page.

### 3. The device — the app's private storage

| | |
|---|---|
| **Location** | `/data/data/<applicationId>/shared_prefs/hermes_bridge_config.xml` |
| **Written by** | `ConfigStore` after a QR scan or manual entry |
| **Protection** | Android app-private storage (other apps cannot read it on a stock device) |

The key is stored in plain `SharedPreferences`, **not** encrypted with
`EncryptedSharedPreferences`. That is a deliberate, documented tradeoff: the
file already sits in app-private storage, and the threat it would defend
against (a rooted device or a full-disk compromise) also defeats the keystore.

## What does NOT contain a secret

- This repository — no key, no `.env`, no keystore (all git-ignored).
- `keystore.properties` — release signing material, kept outside git in
  `%USERPROFILE%\hermes-keys\`.
- Build output and CI logs.

`.gitignore` blocks `.env`, `keystore.properties`, `local.properties` and
`*.keystore`. If you fork this project, keep those rules.

## Rotating the key

1. Edit `API_SERVER_KEY` in the Hermes `.env`.
2. Restart the gateway.
3. Re-run `npx hermes-remote` and re-scan the QR — every device must re-pair,
   because the old key is now rejected.

## Reporting a vulnerability

Open a private security advisory on the GitHub repository rather than a public
issue, and include the affected version and reproduction steps.
